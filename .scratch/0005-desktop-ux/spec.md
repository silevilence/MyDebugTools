# 桌面工作区与首次使用体验

Status: ready-for-agent

## Problem Statement

我手里有一个 DLL，打开软件却先看到“插件管理”。我得先猜“工作台”和“DLL 工作台”的区别，甚至还要知道“DLL 依赖”会出现在另一个插件里面。即使找对了页面，我也要从一长串控件里推断先后顺序。填错进程 ID 时，软件给我一句参数异常，我既不知道改哪里，也很难把有用的信息发给维护者。

这次重构要让第一次使用产品、但了解自己调试任务的人，在每个界面都能回答三个问题：**我正在处理什么？下一步能做什么？这次操作有什么结果？** 现场截图、逐页发现和证据位置见[现状走查](audit.md)。

## Solution

从一个稳定的桌面工作区开始。首页直接提供“查看 DLL 导出或依赖”“监控程序调用”“发送 HTTP 请求”。目标检查和插件管理各有固定入口。用户选择任务后，界面带他到可以实际操作的位置。若需要启用普通插件，就在原处说明用途并提供“启用并打开”。用户返回时仍能接上手里的工作。

各工具按对象和操作顺序组织。以发送请求为例，首屏依次呈现方法、URL、“发送”。发送后在同一工作区看到状态、耗时和响应。连接失败时，地址留在原处，用户可以修改重试，也可以复制诊断信息。DLL、依赖和监控使用相同的操作与反馈规则。

## User Stories

1. 作为首次使用者，我希望按“查看文件”“监控程序”“发送请求”找到入口，以便不查文档就能开始。
2. 作为再次打开工具的人，我希望辨认当前页面、对象和已有草稿，以便继续刚才的工作。
3. 作为只会提供 DLL 或进程 ID 的用户，我希望选择后看到对象、目标架构和可继续的任务，以便一次选好目标。
4. 作为检查运行环境的人，我希望分别看懂宿主架构和目标架构，以及执行时缺哪种运行时，以便继续能做的静态检查。
5. 作为使用插件的人，我希望看出哪些功能已启用、哪些来自本地目录、哪些仅为示例，以便找到真正要用的工具。
6. 作为本地插件作者，我希望添加目录、重载、检查旧版本回收时都看到对应插件的结果，以便判断新版本是否生效。
7. 作为扩展使用者，我希望在当前对象旁找到扩展菜单和页签，在管理页看懂所需和实际契约版本，以便处理部分失配。
8. 作为正在采集的用户，我希望停用或重载前能看见受影响的目标及两个选择，以便决定是否继续采集。
9. 作为浏览 DLL 的用户，我希望只选一个文件便看到目标架构、符号状态及可筛选的导出，以便按名称或序号找到入口。
10. 作为准备调用的人，我希望弄清哪些导出可调用、签名哪些字段已知及来自哪里，以便只补缺少的内容。
11. 作为有 C 声明或本地 PDB 的用户，我希望看到识别的结果、部分失败原因及换版提示，以便核对后确认签名。
12. 作为调试者，我希望按签名填写标量、字符串、结构体和缓冲区，能识别输出参数，以便独立完成一次调用。
13. 作为连续调用的用户，我希望看到当前会话、返回值和输出，并在重置前知道句柄将失效，以便处理异常或超时。
14. 作为生成代码的人，我希望选择当前调用示例或批量声明、语言和格式，以便预览、复制、导出，并查明被跳过的函数。
15. 作为排查缺失依赖的人，我希望从当前 DLL 进入依赖树或依赖图，找到引用方、未解析原因和搜索范围，以便解释结果。
16. 作为验证同名模块的人，我希望直接看见目录优先级，调整后在树、图中核对命中路径，以便验证改动。
17. 作为首次使用监控的人，我希望区分 SDK 和 DLL 导出来源、查看支持程度及已选函数，以便知道能采集哪些信息。
18. 作为监控使用者，我希望分别通过启动程序或附加已有进程进入会话，以便选对目标和位数。
19. 作为正在观察程序的人，我希望随时看到会话、生效时间、调用数、丢失数与停止操作，以便区分等待、采集中和已结束。
20. 作为查看采集结果的人，我希望选择一条调用就能阅读其线程、参数、返回、耗时、调用栈和解码缺项，以便反馈这次事件。
21. 作为接口调试者，我希望输入方法与 URL 即可发送，发送中可取消，以便得到一次临时请求的结果。
22. 作为要上传文件或提交表单的人，我希望正文模式引导我填完字段、选文件并纠正 JSON 错误，以便无需猜测该去哪个页签。
23. 作为接口维护者，我希望在发送时清楚区分实参和默认值，并明确何时保存定义，以便测试数据不会意外成为默认值。
24. 作为查看响应的人，我希望区分 HTTP 错误响应、传输失败、超时和取消，并切换适用的原文、格式化或静态预览，以便判断下一步。
25. 作为使用历史的人，我希望在重启后核对某次请求的实际内容和结果，清空前看清范围，以便保留接口定义。
26. 作为反馈问题的人，我希望在失败处一键复制可预览的诊断摘要，失败时还能手工复制，以便报告可以直接用于排查。
27. 作为使用键盘、小窗口或系统辅助显示设置的人，我希望一直能辨认焦点、选中项、主操作与状态，以便走完同样的任务。
28. 作为插件使用者，我希望在一张可展开的表格里查看所有插件，并从一个界面找到扩展它的插件，以便判断启停会影响哪里。
29. 作为收到插件 ZIP 的用户，我希望在管理页选择包、核对插件并加载，以便直接使用同事提供的工具。
30. 作为清理工具的用户，我希望看清卸载外部包、解除开发目录关联各会动哪些文件，以便只移除选中的插件。
31. 作为同时看输入与结果的用户，我希望能像在 VS 中一样拖动、分栏、合并标签和浮动窗口，以便把正在对照的内容放在一起。
32. 作为偶尔整理桌面的人，我希望从“视图”菜单关闭和找回面板，重开软件能恢复排列，以便随时回到熟悉的工作区。
33. 作为反复调试的人，我希望切换函数、依赖视图或请求日志时保留选中对象及未提交的输入，以便继续刚才的比较。

## Implementation Decisions

### 工作区与页面

| 界面 | 入口、主操作和完成状态 |
| --- | --- |
| 首页与导航 | 默认首页可在首屏看到三项任务及各自用途。稳定导航区区分工作区与管理，当前页有文字、选中标记和页标题。窄窗可收起导航，保留可访问名称和打开入口。插件增减时当前页保持选中。当前页消失时返回上一级或首页并说明原因。 |
| 调试目标 | “选择 DLL”支持浏览和粘贴。“选择进程”明确要求有效 PID。展示文件名或进程名、PID、目标架构。宿主架构另列。可把已选 DLL 带到导出或依赖，把 PID 带到监控准备页，并由用户启动采集。取消选择或输入无效时保留上一有效对象，明确区分尝试打开的对象与当前对象。 |
| 插件管理、确认框与扩展页 | 核心插件、普通插件、示例来源可辨。普通插件显示功能入口或所扩展的界面、启停状态及可用操作。本地添加成功后定位到对应行，失败留在原输入处。失配展示受影响的扩展、所需与实际版本。重载显示进度和结果，卸载检查可复制。正在采集时分别使用“继续监控”“结束采集并停用／重新加载”，关闭对话框等同继续。已有示例工作台、公司插件与页面操作仍能通过公开契约使用。 |
| DLL 导出 | 空页把“打开 DLL”作为主操作。选中后固定显示当前文件、目标架构、导出数与 PDB 状态。长路径可看全和复制。导出表按名称、序号、相对地址、性质对齐。支持筛选、选中和手动输入入口。切分浏览、调用、生成代码的任务。切换时沿用同一文件、函数与已填实参。明确标示静态读取与执行目标代码的边界。 |
| 签名与 DLL 调试会话 | 在字段旁显示来源及“未知／待确认／已确认”。提供返回类型、调用约定、参数行和结构体字段的可见标签、选择项与示例。粘贴声明、PDB 和手工输入汇入同一签名。复杂布局可展开高级文本。文件身份变化时重新确认。调用前指出哪一项还缺。按当前签名给出实参入口并允许 JSON 编辑，结果区分返回值与输出参数。异常后保留输入，说明如何恢复。重启会话前说明已有句柄的影响。 |
| 生成互操作代码 | 显示当前函数示例或批量声明的范围、选择数及既有三种格式。预览区并列给出成功数、跳过数和逐项原因。可用部分仍能复制或导出。按钮区分“复制代码”和“复制诊断信息”，完成时明确已复制或已保存到何处。取消保存时保留预览。 |
| DLL 依赖 | 从 DLL 任务进入并沿用当前文件。未启用插件可在原处启用。区分正在分析、无导入、有未解析项及读取失败。摘要给出静态范围和未解析数。树与图可切换，选择节点见完整路径、导入方、普通／延迟导入、共享／循环、API Set 或具体未解析原因。目录编辑显示完整优先顺序，可浏览、粘贴、上移、下移、移除。刷新后展示新命中位置。两种视图复用同一次解析。 |
| API 监控 | 准备区按“选择函数来源与函数 → 选择目标 → 开始”排列。支持 SDK 搜索及浏览 DLL，多选清单显示数量、重复项和解码能力。启动、附加各只显示相关输入。进行中将所选会话、目标、位数、生效时间、调用数、丢失数和停止操作放在记录旁。会话切换可辨，刷新保留正在阅读的记录。停止后说明目标状态与记录保留期。无记录、未返回和无法解码各用不同文字。 |
| Web API 请求、参数和正文 | 顶部顺序为方法、URL、发送。常用方法可选，自定义方法可输入。超时和取消按需呈现。持续标明“临时请求”或所属目录和接口名。路径、查询、请求头、正文及文件的实参有常驻标签。默认值随参数定义编辑。空、原始文本、URL 编码表单、multipart、二进制文件各有就地下一步。表单可直接添加对应字段或带上下文跳转。JSON 出错保留原文并定位行列。 |
| 接口定义、响应与请求日志 | 定义库提供目录、当前项、新建、打开和保存反馈。替换已编辑请求前允许保留或放弃修改。未发送时给出行动提示。有响应时先呈现状态与耗时，正文和头部可区分，原文始终可取。只展示适用的格式化和 HTML 静态预览入口，标示当前模式。请求日志列出时间、方法、目标与结果，选中后可看实参。空日志禁用或隐藏清空。有数据时明确数量与影响，用户确认后仅清空日志。 |

### 插件管理表与本地 ZIP

默认展示可展开的表格。第一列为名称与层级，其余列为提供的界面或扩展位置、来源、版本、状态、操作。首屏优先保留名称、状态、操作，窄窗将完整路径、插件 ID、契约版本移入行详情。支持键盘展开、按名称查找和切换“全部插件”平表。筛选中命中子项时带出父项。表中插件数按唯一 ID 计算。

- **按实际界面关系组织。** 提供界面的插件在顶层，展开可见相应界面及为其添加菜单或页签的插件。例如“DLL 工作台 → DLL 依赖（依赖页签）”。一个插件既提供页面又扩展多个页面时，主行只管理一次，各父项下用具名引用跳转到同一行。无界面的独立插件也有入口。缺少提供方、契约失配或循环引用始终可找到，层级有限，行详情给出目标与所需／实际版本。折叠、隐藏界面或停用提供方都保留扩展的启用偏好。
- **来源与启用状态分列。** 随附核心、随附普通、外部 ZIP、外部开发目录的标识明确。“普通插件”可随宿主分发，删除权限按来源决定。对未启用的插件，可从包清单读取可选版本、提供的界面及扩展目标元数据。兼容旧的四字段清单和已保存的目录。尚无声明的标“关系待识别”，留在表内，不为排表执行插件；正常启用后按实际注册校正关系。
- **从 ZIP 加载。** 管理页并列提供“加载插件包…”和“关联开发目录…”。本地 ZIP 的根目录放一份既有插件清单、入口程序集和私有依赖。用户选择后预览名称、版本（缺省显示未知）、来源和已有同 ID 插件，再选“加载并启用”。解包到工具管理的独立目录，校验条目路径均在该目录内，拒绝越界路径、重解析链接和缺失入口。准备、注册或启用失败时说明失败阶段并可复制诊断，不留下半安装的行，原有可用版本与布局可继续用。重复导入同一包定位已安装行，同 ID 外部包换版需明确选择替换，内置 ID 冲突就地报错。重启后可从表内找到已安装包。
- **只移除外部插件。** ZIP 行提供“卸载插件…”，确认框显示插件、受影响的界面与扩展、将清理的受管安装位置。开发目录行提供“解除目录关联…”，同时撤下注册并忘记关联，开发者的编译输出和原始 ZIP 均保留。内置行没有删除入口。运行中的采集沿用继续或结束的选择。只在停用完成后清理相应的菜单、停靠面板、订阅与包文件；占用时标明待处理项并可重试。重启后已卸载项不会重新出现，不连带删除其他插件及用户业务数据。

### 可停靠的桌面工作区

首次打开沿用任务首页。进入任务后，中间留给正在操作的主要内容，辅助窗口按上下文出现。例如 Web API 中间编辑请求，下方查看响应，接口目录按需停在左侧。DLL 中间浏览导出或编辑签名，依赖与调用结果可放在侧边或下方。默认就能完成操作；在最小窗口优先以标签切换，让主任务始终有足够空间。

| 用户动作 | 可观察结果 |
| --- | --- |
| 调整排列 | 拖动面板标题时预示放置位置，可停在左、右、上、下，调整分隔条、合并标签、改变标签顺序，或浮动为独立窗口并停靠回来。取消拖动回到原位。面板菜单为键盘用户提供移动、浮动、停靠和关闭命令。 |
| 开启或关闭界面 | “视图”菜单按工作区列出当前可用界面，勾选同步反映打开状态。打开已有界面只聚焦，关闭面板等同隐藏。浮窗关闭、标题栏关闭和菜单操作效果一致。隐藏监控时采集继续，主窗口保留可点击的采集状态。重新打开仍能看到同一会话、选择与未提交草稿。 |
| 重启与恢复 | 按稳定的界面或面板 ID 保存位置、比例、标签顺序、显隐和浮窗边界。重启恢复可用项，不恢复上一次进程的运行中会话。显示器断开时把浮窗带回可见区域；布局数据损坏时回退到默认工作区。“视图 → 恢复默认布局”只重排窗口，现有草稿与运行中工作继续。 |
| 插件停用、重载与移除 | 壳层根据注册项增减菜单和面板。停用或重载时释放旧控件、浮窗、事件和布局模型对插件实例的引用；保存的位置偏好只含标识和值。兼容插件回来后在原位置挂载一次。永久移除外部插件时清理它的布局项。其他面板的尺寸、草稿与选择保留。 |

### 经常重复的操作

| 场景 | 修改要求与通过条件 |
| --- | --- |
| 换函数对照签名 | 同一文件身份下按函数保留未确认草稿，区分“已修改”与“已确认”。从 add 切到另一个入口再切回，未保存字段仍在；换版要重新核对。上一次调用结果标明函数和实参归属，不能被看作新选中函数的结果。 |
| 根据预览复制绑定 | 预览标出函数范围、语言和格式。修改这些条件或实参后，立即刷新预览或明确标记过期并提供更新入口；复制及导出内容须与用户最后看到的有效预览一致。 |
| 从缺失依赖追查来源 | 从“未解析”摘要直接定位具体项，显示父模块及完整引用链，可复制。树与图切换带入所选模块；有多个引用方时保留来路或列出候选。调目录后仍能定位同一条导入，清楚看见“缺失”变成哪条命中路径。 |
| 搜索监控函数与阅读记录 | 搜索空结果给出当前来源和清除筛选入口。已加入、无选择、无会话时分别给出有效操作状态。记录可按会话内的函数或线程筛选，显示匹配数和总数；新记录到达时保持当前阅读位置。清除过滤即可返回完整记录。筛选只影响显示。 |
| 对照 HTTP 实参与响应 | 请求编辑器与响应可并排或上下停靠，缩窄时保留快速切换。响应标明产生它的请求。浏览另一页签期间收到响应时显示完成提示，保留阅读位置。临时请求可以返回未发送草稿；有改动时新建或打开定义可取消。请求日志重开时优先恢复上次选中的记录；记录被淘汰或清空时明确说明。 |

### 视觉、布局与反馈

- 采用 Windows 桌面工具的阅读密度。沿用 Avalonia Fluent 主题资源，统一页面标题、分组标题、正文、字段标签、辅助文字五种角色。建议首版以 24、18、14、14、12 个逻辑像素及 4、8、16、24 的间距构成基线。同一行按基线对齐，结果表按列对齐，数字和代码使用等宽呈现。路径与调用栈可选取。长文本在详情里可看全。
- 每个任务阶段只有一个视觉主操作。主操作用主题强调色与动词文字。返回、浏览、复制等次操作降一级。清空、停止、重启写明对象与影响。分隔线标示功能组，选择态、焦点、错误各有独立线索。普通输入有清晰边界，状态同时有文字或符号。界面图标如需引入，使用同一图标族并随主题和状态取色。
- 在默认 860 × 580 窗口及最小 580 × 400 窗口按逻辑像素验收。宽窗用列表和详情并排，窄窗改为上下布局或进入详情后可返回原位。长列表只滚动内容，当前对象、任务主动作及运行中停止入口可达。页面不出现横向找按钮的情况。依赖画布和长代码允许局部横向滚动。
- tab 切换、输入、选择行和采集刷新即时反馈。采用过渡时仅改变必要属性。键入、行悬停和切页的颜色或透明度过渡最多 150 ms。普通按钮若使用按压缩放，启用态为 0.96、150 ms、ease-out。禁用态保持静止。尊重系统减少动态效果设置，状态变化始终有静态线索。弹窗打开后焦点在弹窗内，关闭后回到发起控件。
- **错误反馈分两层。** 第一层贴着触发点，用中文写清发生了什么、影响哪个对象、能怎么处理。例如空 PID 显示“请输入大于 0 的进程 ID”，输入保留并可直接改正。进程已退出则提示重新选择。第二层是可展开、可选取、可复制的诊断文本，包含产品版本、时间、页面、动作、对象摘要、结果或错误码／原始原因。按场景补充已知的目标架构、插件版本、函数、会话或 HTTP 方法与状态。未知字段明确标明或省略。同一页连续两次失败，复制内容对应用户当前查看的那一次。
- “复制诊断信息”与“复制原文／代码”分开。诊断摘要在本地生成并可预览，默认省略 HTTP 凭据、Cookie、查询实参、正文、缓冲区内容和私人目录前缀，保留定位需要的文件名、字段名、阶段及错误信息。原始异常中的同类值也要处理。剪贴板写入成功提示“已复制诊断信息”，失败时保留可全选的同一份摘要。局部失败逐项列出原因并保留成功结果。
- 使用既有 F#、Avalonia.FuncUI、插件注册契约及 CordiSharp 生命周期。首页按需启用沿用正常启用流程。页面缓存、扩展版本匹配、依赖解析、签名身份检查和会话清理继续使用已有业务逻辑。监控记录停用或重载后可回看、退出宿主时清除。请求日志跨重启保留最近 100 条。发送只记录当次实参，主动保存接口定义才写入默认值。

## Testing Decisions

用户已确认以**真实发布版桌面入口**作为统一验收入口。Windows UI 自动化负责证明动作、界面状态、结果和剪贴板内容正确。首次使用者任务负责判断入口是否能找、流程是否能独立理解。优先复用现有桌面回归、本地 x86/x64 样例、真实 F# 插件及本地 HTTP 回显服务。用用户能看到或粘贴的结果断言，避免绑定布局层数、控件创建顺序或私有状态。

| 验收旅程 | 操作与通过条件 |
| --- | --- |
| A · 第一次启动 | 空配置启动。从首页分别进入三项任务，缺插件时沿页面提示启用并抵达正确位置。依赖定位到当前 DLL 的页签。来回切换工具，未发送 URL、函数选择及其他独立页面草稿保留。示例启用后仍可找到，未启用时不会冒充正式任务。 |
| B · 选择目标与纠错 | 分别选 x86/x64 文件和样例进程，核对目标与宿主位数、下一页带入的对象。空 PID、非数字、已退出进程及不存在的文件各给不同原因。取消选择、选错文件后的活动目标清楚。缺少相应运行时时指出位数，仍可静态浏览 DLL。 |
| C · DLL 导出、签名、调用与生成 | 从本地样例找到 add，确认签名后输入 5 和 7，返回 12。分别覆盖 x86/x64。检查仅序号、数据或未知性质的导出。测试缺字段、部分识别、匹配 PDB、声明粘贴、同路径换版重新确认、复杂参数和连续调用。调用失败可恢复。核对三种代码格式、示例与批量选择，复制内容等于预览，导出的文件一致，部分跳过可读可复制。 |
| D · 依赖树和图 | 打开一次依赖样例，从两种视图找到同一缺失项、引用方与原因。核对共享、环、API Set 及架构不匹配。调整两个同名模块的目录优先级，两处完整路径一致地变化。空依赖、读错文件、切换当前 DLL 时结果归属清晰。 |
| E · 开始、观察与结束采集 | 沿两种来源选函数，用本地 x86/x64 样例分别覆盖启动和附加。核对选中目标实际调用数、生效时间及某条调用详情。区分无调用、未返回、部分解码和丢失。采集期间保持所读记录，停止后目标仍能继续。请求停用或重载时分别走“继续”和“结束”路径。重开插件回看记录，重启宿主后为空。 |
| F · 请求、保存、响应与历史 | 从空 URL 的提示一路发送到本地回显服务。核对方法、参数位置和各类正文／文件的实收值。发送中取消，随后可重试。检查无正文响应、有正文的 HTTP 错误、JSON/XML 格式化、HTML 静态预览、传输失败和超时。用同一定义发两次不同实参，重启后日志各自准确，默认值只在主动保存后变更。试取消替换草稿、取消清空，再确认只清空日志。 |
| G · 插件与页面扩展 | 从管理页添加外部真实 F# 插件，在另一页留草稿，原目录覆盖编译并手动重载两次。新菜单只响应一次、旧页签撤下、独立草稿仍在、卸载诊断可见旧版本回收。制造一个契约版本失配，仅相应扩展撤下，要求与实际版本可复制。恢复兼容只挂载一次。 |
| H · 错误反馈可交付 | 分别触发空 PID、插件目录错误、签名不完整、缺失依赖、监控目标无效、无效 JSON 和 HTTP 连接失败。点“复制诊断信息”后读系统剪贴板，断言时间、对象、动作、真实原因及场景字段与页面一致。用带测试密钥的合成请求验证脱敏。连做两次失败排除过期内容。模拟剪贴板不可写后验证回退文本可全选。恢复后能复制。 |
| I · 可读性与输入方式 | 默认和最小窗口分别走查，至少覆盖 100% 与 200% 显示缩放、浅色与深色、系统高对比度和减少动态效果。保存首页、密集表格、错误、运行中与窄窗截图。键盘完成选择、输入、提交、复制、关闭对话框，焦点可见且顺序符合阅读路径。普通正文对比度至少 4.5:1，关键控件边界和状态标记至少 3:1。 |

### 插件、布局与连续操作的补充验收

验收旅程 A–I 之外，补充以下桌面任务。

| 验收旅程 | 操作与通过条件 |
| --- | --- |
| J · 表格和扩展关系 | 使用真实工作台、DLL 依赖和公司插件，从提供方找到扩展，再从全部插件按名称找回同一行。覆盖多目标、提供方停用、兼容性恢复和缺少关系声明的旧插件。主行计数与已发现的唯一插件一致，关系变化不重复挂载菜单或页签。 |
| K · 加载、替换和移除 | 用已有本地 F# 插件输出制成 ZIP，经界面加载后验证真实页面操作，重启核对来源。分别测试重复导入、同 ID 替换成功、替换失败后旧操作可用、格式错误及路径越界。取消卸载保留插件，确认卸载后页面、菜单和受管副本消失，重启也不回来。核对原 ZIP、外部编译目录、随附普通插件与核心插件仍在。并验证解除目录关联后原目录文件哈希一致。 |
| L · 自由布局 | 从默认布局将请求和响应并排，改成标签，再浮动、隐藏并由“视图”找回。重复打开只聚焦一次，草稿保留。核对键盘路径、重启恢复、显示器减少及恢复默认布局。采集中隐藏监控、重新打开仍见同一会话。插件浮动时重载两次，旧程序集可回收。 |
| M · 连续使用 | 在两个函数间来回编辑、变更代码格式、从缺失项切到图并调整目录、过滤记录并返回、查看旧日志后切走再回来，逐项核对上表定义的草稿、选中对象、路径、计数和复制文本。测试本地 HTTP 延迟响应到达时，正在阅读的页签与焦点保持原处。 |

### 首次使用者任务

找 3 名了解基础 DLL 或 HTTP 概念、没用过本工具的人。采用以下四张任务卡，轮换起始卡以减少熟悉效应。提供本地材料，给出要回答的问题，验收者持有正确答案。不透露插件名、按钮名或操作步骤。

1. “这里有一个 DLL。请告诉我它的位数，再找出一个没找到的依赖及谁引用了它。”提供有已知缺失项的依赖样例。
2. “用给定地址发送两次不同的订单号。请找出第一次发送的值。再用给定的失效地址尝试一次，把足够定位问题的信息贴到空白文本框。”提供本地回显服务。
3. “用提供的样例程序观察指定函数。请告诉我发生了几次调用，停止采集后再找回其中一条。”用样例自身的计数对照结果。
4. “同事给了你一个工具包，请用它提供的操作，告诉我它扩展了哪个界面。把两个需要对照的窗口放在一起，关掉其中一个再找回来。最后移除刚才加进来的工具，留下同事给你的文件。”用本地样例 ZIP，观察用户能否区分关窗、停用和卸载。

记录第一次选择的入口、在哪一步停住、是否需要提示、最终答案、实际粘贴的反馈。不把 UI 自动化通过计作真人完成。每张卡至少 2/3 人独立做对，错误反馈卡的粘贴结果可定位到失败动作与原因且不含测试凭据。若两人卡在同一处，修改后用未接触该任务的新使用者复验。当前只完成规格与基线走查，真人试用安排在可操作的改版上。

## Out of Scope

新增调试引擎、扩展采集能力、增加协议或代码生成语言、云同步、在线反馈上传、插件商店、重写第三方插件内部界面及更换桌面技术栈。此次交付限于排查与修改要求。界面开发按进度表后续实施。

## Further Notes

本次新增外部 ZIP 的本地分发、安装与移除。早期宿主首版的范围和后续扩展见[宿主规格的讨论记录](../0000-plugin-host/spec.md#comments)。

已比较两种布局思路：全流程向导适合首次设置，但在重复调用、切换函数和比对记录时会让人反复翻页。这里选择常驻工作区，只在缺插件、缺签名或缺输入时呈现下一步引导。先修复任务断点、误清空和错误反馈，再统一视觉与动效。实施时以[现状走查](audit.md)复现原问题，以[任务进度](index.md)跟踪改版和验收。
