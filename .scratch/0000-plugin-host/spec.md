# 宿主与插件

Status: ready-for-agent

## Problem Statement

调试不同位数的程序要来回换工具，更新一个第三方插件还可能打断其他页面的工作。第三方功能需要能独立开发和分发。

## Solution

在 64 位 Windows 上打开同一个桌面入口。核心插件随启动就绪，普通插件从本地目录启用、停用或手动重载；界面可以按公开契约接入其他插件。

## User Stories

1. 作为调试者，我希望从一个入口选择 x86 或 x64 目标，以便直接开始调试。
2. 作为调试者，我希望打开工具就有布局、菜单和插件管理页，以便始终能找到管理入口。
3. 作为插件作者，我希望用同一套方式注册核心界面和普通界面，以便复用界面契约。
4. 作为插件作者，我希望声明界面扩展点及其版本和上下文，以便第三方插件独立扩展某个操作或页签。
5. 作为插件作者，我希望从仓库外选择自己的编译目录，以便私有代码独立维护。
6. 作为插件作者，我希望覆盖编译到原目录后手动重载，以便立即验证新版行为。
7. 作为调试者，我希望停用普通插件时撤下它的界面和菜单，以便随后重新启用时只看到一份。
8. 作为调试者，我希望重载期间其他页面保留输入，以便接着完成手上的工作。
9. 作为调试者，我希望看到不兼容扩展要求的版本和实际版本，以便知道该更新哪个插件。
10. 作为调试者，我希望停用正在监控的插件前能选择继续或结束采集，以便掌控当前会话。

## Implementation Decisions

- F# 与 Avalonia.FuncUI 构建界面。优先用 F# 开发，确需自建 C# 项目时在该项目留下 Markdown，说明 F# 遇到的具体限制与 C# 的职责。框架依赖发布，建议以 .NET 10 作为构建基线。
- 首版宿主为 Windows x64。将宿主架构与目标架构分别表达，按目标 DLL 或进程选择执行环境；缺少对应架构的运行时时指出缺项。保留未来增加 32 位宿主的可能。
- CordiSharp 管理作用域与生命周期。界面注册方式统一，宿主决定核心插件的固定加载策略。普通插件既可提供界面，也可消费扩展点。
- 提供方声明稳定的界面 ID、扩展点 ID、契约版本、可接入的内容与上下文。消费方声明目标与兼容版本。提供方撤下时保留扩展的启用偏好，恢复后重新挂载。
- 记住选定的本地目录，允许插件启用期间在原目录完成编译。手动重载时撤销旧的菜单、订阅和后台工作，重新注册新版。版本失配按扩展处理，管理页列出具体原因，其他兼容扩展可用。
- 监控会话仍在采集时显示目标进程。用户决定前继续采集；选择结束后先完成停止，再停用插件。

## Testing Decisions

- 仓库目前只有需求文档，尚无现成自动化用例。以下从用户入口核对可观察结果，优先复用本地测试资源。
- 从正常桌面入口验证固定核心和普通 F# 页面。用带不同私有依赖的样例插件分别启停，观察菜单、响应次数及诊断信息。
- 在独立页面留一份未发送的输入。重编译到原目录并重载，执行菜单验证新版结果、只有一次响应，原有输入仍可使用。用一个兼容和一个失配扩展核对局部停用。
- 以反复重载并实际覆盖文件验收开发体验。另以卸载诊断核查旧程序集能否回收，不能仅凭页面消失判定。监控中的停用由监控规格的真实会话补验。

## Out of Scope

32 位 Windows 宿主的发布、核心插件运行中卸载、自动监听编译并热更新、插件商店与插件包安装不列入首版。
