# 第三方插件开发 MCP

Status: ready-for-agent

## 开发者的操作

1. 在插件管理页打开开发模式，复制连接配置到本机 MCP 客户端。重启后原配置继续可用；关闭开关即停止服务。
2. 从客户端读取当前宿主版本对应的文档，包括插件清单、公开注册契约、可用扩展类型、上下文及安装、卸载临时插件的示例。
3. 指定本机编译输出目录安装临时插件。桌面显示本次快照的插件 ID 和来源目录，由用户逐次确认后生效。可以重新编译到同一目录并再次安装。可随时卸载临时版，宿主重启后自动恢复日常使用的配置。

## 查询结果

| 开发者要了解的内容 | 返回结果 |
| --- | --- |
| 已安装及当前运行的插件 | 同时列出正式与临时来源、插件 ID、可获得的版本信息、启用状态、当前生效版本及失败或失配原因。区分正式版已停用与被临时版接替。缺少版本信息时说明未知。 |
| 有哪些界面 | 仅返回当前已注册界面的稳定 ID 和功能说明。 |
| 某个界面如何扩展 | 按界面 ID 返回说明和公开扩展点，每个点给出 ID、种类、契约版本、可接入内容及可用上下文。区分未知界面与已注册但无扩展点的界面。 |
| 全部界面及扩展点 | 一次返回与逐界面查询一致的完整结果，包括当前没有扩展点的界面。 |

查询反映同一时刻的有效注册。发现扩展点无需实例化界面控件或执行菜单动作。现有公开契约提供 ID、标题和部分类型信息，新增功能说明应兼容旧版插件；旧插件未声明的字段明确标示。插件启停、替换、失败恢复后都能查询最新状态。

## 切换与恢复

| 场景 | 预期行为 |
| --- | --- |
| 首次安装临时版 | 复用编译目录快照、私有依赖隔离和 CordiSharp 作用域；正式安装清单不写入临时项。 |
| 已有同 ID 的正式普通插件 | 记录原启用偏好并接替；任一时刻最多一份生效。卸载临时版或重启后恢复原来的启用或停用状态。核心插件仍按固定加载规则管理。 |
| 同 ID 临时版再次安装 | 从当前目录取得新的独立快照，释放旧界面、菜单、订阅和后台工作，新版只注册一次。其他页面输入及工作状态保留。 |
| 新版加载失败 | 撤销全部部分注册，恢复上一次可用快照和启用状态，经 MCP 返回插件 ID、出错阶段和原因。覆盖编译失败、激活中途抛错都可重复尝试。 |
| 切换或卸载会中断采集 | 桌面用户选择继续，或先结束采集再操作。取消时当前版本继续运行，MCP 返回实际结果。 |

同一 ID 的并发写操作按顺序处理。卸载只移除临时登记及其宿主管理的快照，保留开发者编译目录。异常退出后按正式安装记录和原启用偏好启动。

## 本机连接

建议采用 Streamable HTTP。初始关闭，只监听回环地址；复制的配置含稳定本机地址和对应凭据。验证请求来源及凭据；端口被占用时在管理页显示具体原因，保留已保存的配置。文档及查询接口与当前桌面宿主共享状态。[MCP 传输规范](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports)

## 验收

从管理页和真实本机 MCP 客户端操作，以真实 F# 插件、CordiSharp 作用域和 FuncUI 页面交叉核对。覆盖三种界面视图、无扩展点、旧契约、停用的提供方、正式版启用及停用、纯临时插件、同 ID 覆盖两轮和坏版本恢复。核对菜单实际响应次数、其他页面草稿、旧程序集回收，以及重启后的正式版状态。
