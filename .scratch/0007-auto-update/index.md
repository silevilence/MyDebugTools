## 本地验收

- 测试宿主内置独立测试公钥和回环 HTTP 清单地址。从 1.0.0 检查 1.0.10，说明正文正确。稍后及再次检查只请求清单和签名，同版、旧版均可继续工作。
- 服务器分别返回被改动的清单、HTTP 503、同长度但内容错误的安装包。宿主显示失败原因后可重试。测试插件拒绝停止时宿主保留，并显示插件提供的原因。
- 附加真实样例后，选择继续采集，下一次调用仍返回 103 并写入记录。再次确认结束采集后旧宿主退出，目标继续运行并返回 104。新版恢复插件和工作区，HTTP 定义与日志可用，监控会话列表为空。
- 有效安装包只从本地 HTTP 源传输一次，后续交接复用已校验缓存。此轮使用测试公钥与本地安装包。
- 全量 .NET 回归共 54 项，最终全部通过。首次并行运行时，一项既有的 x64 并发采集用例预期 2 条、实收 3 条。单独重跑原生测试和再次运行全套均通过。

## 正式更新验收

- 2026-11-24，使用首版发布前提交 `8819635` 和本机依赖缓存构建 0.9.0 验收安装包，嵌入正式公钥并使用默认 GitHub 地址。0.9.0 仅用于此次验收。旧版从开始菜单启动，读取签名清单，显示的六条说明与 V1.0.0 的发布正文一致。[正式 Release](https://github.com/silevilence/MyDebugTools/releases/tag/V1.0.0)
- 沙盒直连发生超时和连接重置，首次下载也被验收脚本的等待上限中断。延长等待后，使用仅接受该沙盒访问 GitHub 及其 Release CDN 的临时 HTTPS 隧道完成一次完整下载。应用使用原始正式地址，执行 TLS、清单签名和安装包签名校验。首次确认前已验证安装包缓存为空。
- 旧宿主退出时，界面自动化失去旧窗口。随后从安装快捷方式核对宿主版本为 1.0.0，并以更新缓存中的同一安装包对照 GitHub 摘要及 14,648,822 字节大小，无需再次下载。
- 从开始菜单重新启动正式版，「检查更新」显示当前已是最新版本。外部插件仍启用，保存的接口和 HTTP 200 日志均可查看。升级前后的插件登记、接口定义、请求日志三个文件 SHA-256 一致。
