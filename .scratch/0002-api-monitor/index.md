| 启动、附加和调用详情 | 两种位数的原生样例各调用所选函数 10 次，并交错调用另一个导出。发布界面只收到各自的 10 条记录。定向测试逐次核对参数、返回值、线程、调用栈及观测耗时。对 .NET 父子进程分别附加，核对附加前、停止后的调用均在采集范围之外。 |
| 并发、未返回与丢失 | 两个线程的 SleepEx 按各自入参和返回配对。采集中止时长调用由「进行中」变为「不完整」，目标随后正常返回。将测试容量设为 3，10 次调用保留 3 条、报告丢失 7 条。 |
| 发布版与热更新 | Windows UI 自动化验证停用对话框显示目标、等待期间继续采集。将插件替换为另一个实际构建并重载后，原会话第一条记录的参数、返回值、调用栈和时间与更新前逐字相同。重启宿主后历史为空，再从 SDK 目录直接采集 GetSystemTime。 |

首版记录整数、句柄和地址。指针内容与暂不能解码的字段在详情中标为未知。每个会话保留最先采到的 10,000 条，之后显示丢失计数。耗时取自调试器观察到的进入与返回时刻，包含调试开销。
