# 程序调用 C ABI DLL 监控

Status: ready-for-agent

## Problem Statement

调试业务程序时，用户需要知道选定的 DLL 函数何时被调用、由谁调用、收到了什么参数以及返回了什么。手动复现一次调用无法还原原程序中的顺序和现场。

## Solution

从 DLL 导出或内置 Windows API 目录勾选函数，启动或附加当前用户的程序，逐次查看记录。监控插件更新后可以继续查看本次打开工具期间的历史。

## User Stories

1. 作为调试者，我希望从 DLL 导出中多选函数，以便聚焦当前问题。
2. 作为调试者，我希望直接搜索广泛的 Windows SDK API 定义，以便省去手选系统 DLL。
3. 作为调试者，我希望在采集前看到函数支持情况和可解码字段，以便预判能取得的信息。
4. 作为调试者，我希望由工具启动目标或附加已有进程，以便覆盖两种调试现场。
5. 作为调试者，我希望从同一入口监控 x86 和 x64 目标，包括调用原生 DLL 的 .NET 程序，以便复用我的操作习惯。
6. 作为调试者，我希望每个会话只记录选中的进程，以便区分父子进程的调用。
7. 作为调试者，我希望逐次查看线程、调用栈、入参、返回值及用时，以便重建调用过程。
8. 作为调试者，我希望看出未返回、无法解码或丢失的记录，以便判断证据是否完整。
9. 作为调试者，我希望能结束采集并让目标继续运行，以便在同一程序中继续工作。
10. 作为调试者，我希望热更新后仍能回看已有记录，并在退出主程序时清除，以便按本次调试整理结果。

## Implementation Decisions

- 首版覆盖当前用户启动的普通桌面和命令行程序，目标架构为 x86/x64，包含 .NET 调用原生 DLL。启动和附加都显示采集生效时间。
- 支持 DLL 导出选择与 Windows SDK API 目录两种入口。共享 DLL 调试的函数签名，逐函数说明可监控、可部分解码或当前不支持的原因。
- 将每次选中函数的调用归入所属进程、线程和会话。记录入参、返回值、耗时和调用栈。缺少符号时保留模块与偏移，缺少类型时标示未知，明确显示进行中、不完整和采集丢失的情况。
- 子进程由用户另行附加。停用时提示当前进程，继续监控保留同一会话；结束采集并停用时让目标继续运行。
- 监控记录保留至本次主程序退出，停用和重载后可在原会话查看详情。

## Testing Decisions

- 仓库目前只有需求文档，尚无现成自动化用例。以下从用户入口核对可观察结果，优先复用本地测试资源。
- 在工具页面勾选函数，让可控目标以已知参数调用十次。分别使用启动和附加，按生效时点核对次数、参数、返回值、调用栈与用时；覆盖 x86/x64、并发调用和 .NET 调用原生 DLL。
- 父子进程调用同一函数时分别核对归属。比较可完整解码、部分解码和不支持条目的预告与实际结果；覆盖不完整记录及丢失可见性。
- 从管理页选择继续监控，确认新记录进入同一会话；再次选择结束并停用，目标继续运行。重载后核对旧记录详情，退出并重启后历史为空。

## Out of Scope

自动跟随子进程、Windows 服务、跨主程序重启保留监控记录，以及追溯附加生效前的调用不列入首版。

## Further Notes

验收使用可控的本地样例，按目标自身可核对的调用次数判断覆盖。具体 SDK 目录来源与可解码范围需在实现时记录。
