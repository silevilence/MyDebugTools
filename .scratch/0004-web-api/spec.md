# Web API 调试与接口定义管理

Status: ready-for-agent

## Problem Statement

用户既要临时试一个 URL，也要维护可反复调用的业务接口。调试时改动的实参容易混入接口默认值，HTTP 错误网页和连接失败也需要不同的查看方式。

## Solution

提供临时发送和按内部目录管理接口定义两种入口。每次发送独立记日志，展示原始响应及适合内容类型的视图。

## User Stories

1. 作为调试者，我希望输入 URL 和常用或自定义 HTTP 方法即可发送，以便快速试接口。
2. 作为调试者，我希望在软件内部按目录保存和重开接口定义，以便组织工作接口。
3. 作为接口维护者，我希望定义参数名称、位置、类型、必填状态、说明及默认值，以便约定可复用。
4. 作为调试者，我希望每次发送独立填写实参，以便试不同值而保留原默认值。
5. 作为调试者，我希望编辑路径、查询、请求头与正文，以便还原实际请求。
6. 作为调试者，我希望发送文本、URL 编码表单、带文件的表单和二进制文件，以便调试常见上传及数据接口。
7. 作为调试者，我希望编辑 JSON 时能高亮、格式化及定位错误，以便保留原文并修正。
8. 作为调试者，我希望看到响应状态、耗时、头部和原文，以便判断是服务端响应还是传输失败。
9. 作为调试者，我希望格式化 JSON/XML、预览 HTML 错误页，以便直接读懂返回内容。
10. 作为调试者，我希望重启后仍能查到最近实际发送的参数，以便对照昨天成功的调用。
11. 作为调试者，我希望能清空日志并继续使用接口定义，以便分别管理配置与历史。

## Implementation Decisions

- 目录组织接口定义和参数定义，作为软件内部资源持久化。临时发送和从定义发送都产生独立请求日志。仅主动保存定义才更新它及其默认值。
- 每项参数定义记录名称、位置、类型、是否必填、说明与可选默认值。支持合法自定义 HTTP 方法，遇到底层限制时显示原因。
- 正文支持空、原始文本（含 JSON/XML）、URL 编码表单、文本和文件混合的 multipart、二进制文件。JSON 格式错误时保留原文并定位。
- 响应可查看状态码、耗时、响应头、原文；JSON/XML 格式化和高亮，HTML 支持禁用脚本和远程资源的静态预览。区分 HTTP 错误、连接失败、超时及取消。
- 请求日志跨重启保留实际发送参数及结果信息，可手动清空。达到保留上限时淘汰最旧记录。具体上限数值尚未指定。

## Testing Decisions

- 仓库目前只有需求文档，尚无现成自动化用例。以下从用户入口核对可观察结果，优先复用本地测试资源。
- 用本地回显服务，从定义按默认值 1001 和临时值 1002 发送，核对服务器实际收到的值、两条独立日志及重开后的默认值。重复一次临时发送，确认目录未新增定义。
- 通过同一界面覆盖各类方法、参数位置与正文。核对编码和上传文件内容。分别返回 JSON、XML、HTML 错误页及无效 JSON，核对展示、错误提示与原文。
- 关闭再启动后核对接口定义与请求日志。以已知上限验证淘汰顺序，清空后再次使用相同接口定义发送。

## Out of Scope

团队云同步、脚本自动化、集合批量运行以及将内部目录映射为用户维护的磁盘目录不列入首版。

## Further Notes

请求日志与 DLL 监控记录有不同保留期限。HTTP 日志跨重启保留，DLL 监控记录在本次退出时清除。
