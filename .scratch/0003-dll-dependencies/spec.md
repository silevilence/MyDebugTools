# DLL 依赖链

Status: ready-for-agent

## Problem Statement

用户发现 DLL 缺少依赖时，需要追到具体是哪一层缺失，还要知道同名文件究竟解析到了哪个目录。切换工具和重新选文件会打断分析。

## Solution

在当前 DLL 工作台的“依赖”页签查看依赖树与依赖图，调整搜索目录后立即看到实际命中路径及新的下级依赖。

## User Stories

1. 作为调试者，我希望打开 DLL 后直接切换到依赖页签，以便沿用当前文件。
2. 作为调试者，我希望展开每层普通导入与延迟导入，以便追到缺失来源。
3. 作为调试者，我希望在图中看到共享依赖和环，以便理解多个分支之间的关系。
4. 作为调试者，我希望识别 API Set 合约及其解析目标，以便理解系统依赖。
5. 作为调试者，我希望看到缺失和架构不匹配的原因，以便选择正确的 SDK 或目录。
6. 作为调试者，我希望添加和调换搜索目录，以便复现我的应用使用的依赖布局。
7. 作为调试者，我希望树和图同时显示新的完整路径和下级依赖，以便核对同名模块的选择。
8. 作为调试者，我希望单独启停依赖插件，以便按需在工作台使用这个页签。

## Implementation Decisions

- 依赖分析是可独立启停的普通插件，接入 DLL 工作台的页签扩展点，读取其当前文件。
- 递归分析普通和延迟导入。标明共享节点和环，在环处结束该分支展开。区分 API Set 合约与当前环境中解析到的宿主。
- 解析时考虑目标架构和搜索目录顺序，显示命中的完整路径与未解析原因。树和图使用同一次解析结果。
- 添加或调换目录后立即重算，命中变化时相应替换下级依赖。静态分析结果说明获取范围。

## Testing Decisions

- 仓库目前只有需求文档，尚无现成自动化用例。以下从用户入口核对可观察结果，优先复用本地测试资源。
- 从工作台打开一次 DLL，在导出与依赖间切换。验证独立启停、普通与延迟导入、缺失、错位数、环和共享节点。
- 复用有两份同名、同架构依赖且下级依赖不同的本地样例。初次解析缺失，添加目录后解析成功，再调换顺序，从树和图核对两次完整路径和下级依赖。

## Out of Scope

跟踪程序运行后动态拼接或选择的模块名称不属于静态依赖分析。

## Further Notes

“命中路径”指按本次分析的环境与目录解析到的文件。运行现场的搜索条件可能不同。

- [Windows PE 格式](https://learn.microsoft.com/en-us/windows/win32/debug/pe-format)
