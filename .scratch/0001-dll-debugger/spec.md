# C ABI DLL 调试

Status: ready-for-agent

## Problem Statement

用户通常只有一个原生 DLL。即使知道导出名，也可能缺少参数类型、调用约定和返回类型，手写互操作声明还容易与实际调用不一致。

## Solution

在 DLL 工作台打开文件，查看导出并补齐签名；从同一入口调用 x86 或 x64 DLL，复用会话状态，并根据确认过的签名生成 C# 和 F# 声明及调用示例。

## User Stories

1. 作为调试者，我希望只凭 DLL 查看架构、导出名和序号，以便判断可用的入口。
2. 作为调试者，我希望识别转发、数据或性质未知的导出，以便判断能否调用。
3. 作为调试者，我希望看到签名各字段的来源和缺项，以便结合手边任意语言的示例补全信息。
4. 作为调试者，我希望利用匹配的本地 PDB 或内置 API 定义，以便减少重复录入。
5. 作为调试者，我希望粘贴 C 函数和结构体声明，并能定位未知类型或宏，以便补齐后确认。
6. 作为调试者，我希望选中或手输入口并填写参数，以便查看返回值和输出参数。
7. 作为调试者，我希望使用字符串、缓冲区和结构体字段，以便测试业务 DLL 接口。
8. 作为调试者，我希望连续打开、读取和关闭句柄，以便测试依赖前序调用的函数。
9. 作为调试者，我希望异常或超时后保留输入并重新开始，以便恢复调试。
10. 作为调试者，我希望同一 DLL 重开后复用签名，换版时核对候选，以便避免按旧签名调用新版函数。
11. 作为开发者，我希望复制 C# 或 F# 的调用示例，以便在自己的程序中复现结果。
12. 作为开发者，我希望多选函数后复制或导出三种声明，以便一次完成一组互操作绑定。

## Implementation Decisions

- 静态读取 PE 架构、导出名、序号、相对地址及转发目标。显示能判定的数据导出、可调用函数和未知项。浏览阶段无需执行目标 DLL。
- 共用一份签名描述供调用、监控和代码生成使用。保存返回类型、参数类型与方向、调用约定，以及相关的字符串编码、缓冲区长度和所有权；缺失字段保持未知。
- 同目录发现的 PDB 先核对与 DLL 的匹配关系，只补入可取得的类型信息。C 声明粘贴支持部分识别，保留原文位置与已识别字段，用户可补齐后确认。
- 已确认签名跨会话和重启保存。识别同一份 DLL 时考虑文件身份；同路径、同导出名的新版 DLL 也须重新确认旧签名。
- 需要执行时自动选择与目标同位数的后台进程。支持整数、浮点数、句柄、明确编码的字符串、已知长度缓冲区、输出参数和可按字段描述的普通 C 结构体。按目标架构解释字段布局。
- 同一调试会话沿用加载实例。重新开始会话后旧句柄失效。后台异常或超时后保留用户输入并呈现可恢复状态。
- 输出 C# DllImport、C# LibraryImport 和 F# DllImport，支持单个示例、多选复制与文件导出。遇到某输出形式无法表达的签名时，逐项说明原因，其他可生成项继续输出。

## Testing Decisions

- 仓库目前只有需求文档，尚无现成自动化用例。以下从用户入口核对可观察结果，优先复用本地测试资源。
- 通过同一工作台打开已知导出与结果的 x86、x64 样例。比较仅有 DLL、匹配且有类型的 PDB、匹配但缺类型的 PDB、错版 PDB；核对信息来源和缺项。
- 粘贴完整与含未知类型的声明；确认后保存并重开。替换同路径的 DLL，验证旧签名进入待确认状态。
- 调用带状态、句柄、字符串、输出缓冲区和结构体的已知函数，核对结果及重置行为。后台失败后主窗口保留输入。
- 分别编译三种生成物，执行生成的 C#、F# 示例，对照同架构样例 DLL 的预期结果；混合选择可生成与不可生成项时核对导出清单。

## Out of Scope

自动理解任意示例语言、完整 C/C++ 项目预处理、回调、可变参数与在线符号服务器不列入首版。

## Further Notes

用户通常没有头文件或符号，只有 DLL 的浏览和手工录入流程须独立成立。
